관전 포인트
================================================================================
1) workflow 블록 신설 (16~21행): GitLab 권장 표준 패턴 그대로 채택.
   - rule 1: MR pipeline은 항상 통과
   - rule 2: branch에 열린 MR이 있다면 branch pipeline 차단 (when: never)
   - rule 3: 그 외 branch pipeline 허용 (MR 없는 feature push, develop/main merge)

2) unit-test / checkstyle / frontend-build 의 rules 변경:
   - 기존: changes만으로 매칭 (branch / MR 모두 동일하게 매칭)
   - 변경: merge_request_event / CI_COMMIT_BRANCH 두 분기를 명시
   - 이유: workflow 블록과 잡 rules는 AND 조건. 잡 rules에서 source를 명시하지 않으면
     workflow 통과 후 잡이 무조건 매칭되어 의도치 않게 켜질 수 있음. 이중 안전장치.

3) package 잡 rules 최상단에 'if MR_event then never' 추가:
   - GHCR 이미지 푸시는 검증된 head 코드(branch pipeline 머지 commit)에서만 실행.
   - MR pipeline에서는 unit/integration/checkstyle/frontend-build로만 검증.
   - 검증되지 않은 MR commit이 GHCR에 :SHA 태그로 누적되는 것을 차단.
