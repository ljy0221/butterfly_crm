## C. 기능 점검 (시연 흐름 그대로, 7분)

발표 시연 흐름과 동일 순서로 빠르게 클릭만 해본다. 실제 발송은 Stub 어댑터 사용.

### C.1. 로그인 → 프로젝트 진입
- [ ] 로그인 화면 → OPERATOR 자격 증명 입력 → 대시보드 진입
- [ ] 다른 프로젝트 URL 직접 입력 시 차단 (403 또는 권한 없음 메시지)

### C.2. 대시보드 KPI 확인
- [ ] 6개 KPI 카드 표시 (sent / delivered / open / click / convert / audit)
- [ ] 모든 카드에 숫자가 보임 (`-` 또는 `null` 없음)
- [ ] KPI 정의서와 표시 정의 일치 (마우스 오버 툴팁 등)

### C.3. 세그먼트 생성 + 미리보기
- [ ] 세그먼트 빌더에서 조건 1개 추가 → 미리보기 → targetCount 표시
- [ ] 저장 → 세그먼트 목록에 표시

### C.4. 캠페인 생성 + 발송
- [ ] 새 캠페인 → 세그먼트 선택 + 템플릿 선택 → 즉시 발송
- [ ] 발송 결과 페이지에서 5건 발송됨 확인
- [ ] 캠페인 성과 화면 진입 → 5 sent / OPEN/CLICK 카운트 표시

### C.5. 분석 리포트
- [ ] 펀널 리포트 → 5 발송 → OPEN → CLICK → CONVERT 단계별 모수 표시
- [ ] 세그먼트×채널 매트릭스 → 표 형태로 카운트 표시
- [ ] CSV 다운로드 1회 클릭 → 파일 다운로드 OK

### C.6. 감사 로그
- [ ] `/audit-logs` 진입 → 최근 로그인/캠페인 활성화 등 표시
- [ ] CSV 다운로드 → 다운로드된 파일에 row 존재

### C.7. 권한 격리 시연
- [ ] OPERATOR로는 멤버 권한 변경 메뉴 비활성/숨김
- [ ] OWNER 로 재로그인 시 권한 변경 가능

## E. 알려진 한계 (발표 시 미리 언급)

데모 시 다음 내용은 **사전에 인지하고** 질문 받았을 때 자연스럽게 설명할 준비:

| 한계 | MVP 범위 외 사유 | 향후 계획 |
|---|---|---|
| 실제 FCM/APNS 채널 연동 | 외부 인증·계약 필요, 데모 안정성 우선 | Sandbox FCM 연동 후 stage 검증 |
| 매출 기여 분석 (revenue, ROI) | DB 컬럼 미정, 빌링 도메인 인터페이스 필요 | KPI 정의서 §3.3 — 별도 ADR + 마이그레이션 |
| A/B 테스트 메시지 버전 | MVP 우선순위 외 | Phase 2 |
| 카카오/SMS/이메일 채널 | MVP 범위 외 | Phase 2, 채널 어댑터 추상화는 이미 적용 |
| 코호트 / 리텐션 분석 | 데이터 누적 시간 부족 | Phase 2 |
| 실시간 발송 모니터링 화면 | MVP 우선순위 외 | Phase 2 |

## F. 비상 대응

| 상황 | 1차 대응 | 2차 대응 |
|---|---|---|
| 발송 워커 멈춤 | 워커 재시작 | 백업 영상 재생 |
| DB 응답 느림 | 집계 테이블 우선 조회 (이미 적용) — 화면은 정상 | DB 컨테이너 재시작 |
| 인증 실패 (백업 자격 증명도 안 됨) | OWNER 권한 다른 멤버 자격 증명 | 백업 영상 재생 |
| 전체 시스템 다운 | 백업 영상 재생 + 발표 슬라이드만 진행 | — |
| KPI 숫자 0 표시 | daily 롤업 force 재실행 (시연 직전 5분) | 사전 시드 데이터 풍부하게 |

**원칙**: 발표 중 막히면 백업 영상으로 즉시 전환. 막힌 화면 보면서 디버깅하지 않는다.

## G. 체크리스트 사용법

리허설 1회 = 체크리스트 1회.

각 리허설 시작 시 본 문서 사본을 만들어 (`02-demo-checklist-rehearsal-{N}.md`) 통과/실패 표시.
3회 연속 모두 통과하면 발표 준비 완료. 1회라도 실패한 항목은 다음 리허설 전에 수정.
